# 决策矩阵与分层拆解（SKILL.md 的补充细节）

## 受众四问的追问清单

### Q1 受众是谁（决定语言、深度、格式）
| 受众 | 语言风格 | 术语策略 | 默认机制 |
|---|---|---|---|
| 决策层（CEO/领导/客户高层） | 结论先行，商业语言 | 零术语，全部翻译成人话 | C 或 A（一句话版先行） |
| 技术同行 | 精确、可验证 | 术语保留，给引用 | A + B |
| 新员工/学生 | 类比驱动，循序渐进 | 术语首次出现必解释 | C 或 D |
| 跨部门/公众 | 故事线，去黑话 | 术语表放文末 | C + B |
| 未来的自己 / AI agent | 结构化、无歧义 | 严格术语表（STE100） | A |

### Q2 他们卡在哪（决定讲解策略）
- **缺背景知识** → 从共识区出发，用类比桥接；前置一个"你已经知道的 X 就像……"
- **有错误先入之见** → 不要正面否定，先承认其合理性，再展示反例/边界情况
- **立场对立**（如预算审批被挑战）→ 机制 E（演示工具）优于机制 A（文字辩护）：让数据自己说话
- **没时间** → 一句话版本 + 附录结构；把细节全部下沉到支撑层

### Q3 他们已经相信什么
先写一句"我们都同意……"再进入新内容。找不到共识点 = 还没准备好讲解，先做调研。

### Q4 读完要做什么（决定工件类型）
| 行动 | 工件 |
|---|---|
| 批准/决策 | C（HTML 简报）或 A（单页备忘录） |
| 学会操作 | D（视频）或 C（交互教程） |
| 改变看法 | B（论证图）或 E（自助数据工具） |
| 存档备查 | A（STE100 文档） |
| 培训他人 | D + B（视频配图解） |

## 分层拆解模板

### 一句话版本（≤30 字）
句式：`[主体] 用 [机制] 让 [对象] 实现 [结果]`。
例："用 AI 讲解方法论，让任何复杂内容匹配到最合适的呈现方式。"

### 三句话版本
1. **背景**：为什么这件事存在（共识区）
2. **核心**：它是什么、怎么工作（新增信息）
3. **意义**：对受众意味着什么（行动指向）

### 分段版本（默认交付层）
每段一个论点，段首句 = 该段结论（倒金字塔）。层间过渡句必须回答"所以接下来自然要问什么"。

### 支撑层
证据、数据、边界情况、来源。放在文末附录，正文用 `[附录 A]` 引用。

## 升级 / 降级规则（何时不满足）

- 讲解被反馈"看不懂"→ 先换机制（矩阵里相邻机制），再考虑加细节；**加细节是最后手段**
- HTML 工件被反馈"花架子"→ 降级为 A（纯文本 STE100）+ B（一张核心图）
- 视频被反馈"节奏慢"→ 砍脚本而不是加速画面；脚本 > 80 秒先减半
- STE100 文本被反馈"生硬"→ 检查是否误用于说服场景；若是，换 C（HTML 故事线）

## 组合工作流示例

**"把这份工业设备监测技术方案讲给集团领导"**
1. Q1-Q4：领导 / 可能先入之见是"AI 方案虚" / 共识是"设备事故损失大" / 行动是批准试点
2. 矩阵：决策层 + 需要改变看法 → 主机制 C（单页 HTML 简报），论据层用 B（一张架构图）
3. 分层：一句话版开场 → 三句话版摘要 → 三段正文（痛点共识/方案机制/试点收益）
4. 自检：开头 30 秒有一句话版；图表每个元素有存在理由；无 AI 默认设计
5. 交付 + 建议："如需上会汇报版，我可以再加一个 60 秒 Manim 视频"
