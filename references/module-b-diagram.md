# 模块 B：图表（Diagrams That Argue）

**定位**：用空间布局表达逻辑结构。适用于：系统架构、流程、因果链、对比、层级、时间线。
**不适用**：纯数值对比（用表格）、情感表达、任何"装饰性配图"。

## 讲者模型（生成每一张图前过一遍）

1. **我希望受众的眼睛按什么顺序移动？** → 布局必须引导这个顺序（阅读方向、箭头、对比位置）
2. **我希望他们生成什么心智模型？** → 图的结构必须就是这个心智模型，不是数据的罗列
3. **哪些视觉元素是论证的一部分？** → 每个元素必须能回答"为什么在这"（参考：mgranberry/mermaid-diagram-skill 的理念：diagrams that argue, not display）

## 修辞映射（逻辑 → 图形）

| 要表达的逻辑 | 图形选择 | 空间隐喻 |
|---|---|---|
| 一对多/扇出（部署、分发） | flowchart 放射状 | 中心向外 = 扩散 |
| 时间序列（流程、演化） | sequence / timeline | 从左到右 = 时间流逝 |
| 收敛/聚合（多源归一、汇总） | 多箭头汇合节点 | 向内 = 汇聚 |
| 层级/包含（组织架构、模块） | graph TB 树状 | 上 = 高抽象层 |
| 对比/张力（方案 A vs B） | 左右对称双栏 graph | 距离 = 分歧程度 |
| 循环/反馈（闭环控制、迭代） | flowchart LR 环状 | 回到原点 = 循环 |
| 因果链（故障树、逻辑推导） | 自上而下 + 条件菱形 | 上游 = 因，下游 = 果 |
| 状态切换（协议、生命周期） | stateDiagram-v2 | 状态 = 位置，转换 = 路径 |

**规则：形状和布局承载逻辑，颜色只承载语义**（危险=红、通过=绿、信息流=蓝、控制流=橙）。禁止用颜色装饰。

## 生成流程

1. 先用一句话写出"这张图要让人明白什么"
2. 从上表选图形（找不到对应 → 该内容不适合用图，回矩阵换机制）
3. 写 Mermaid 代码；节点文字 ≤ 8 字，长句必须压缩
4. 渲染验证：`scripts/env_check.py` 探测 mermaid-cli；可用则本地渲染并自查，不可用则输出 .mmd 文件 + mermaid.live 链接
5. 对照清单自检后交付

## 验收清单

- [ ] 图中每个元素能回答"为什么在这、为什么是这个形状"
- [ ] 删掉任何一个元素都会损失信息（否则就该删）
- [ ] 受众 3 秒内看懂图的"流向"，30 秒内复述图的主旨
- [ ] 没有超过 9 个节点的平面团（信息过载 → 拆成多张或上分层）
- [ ] 颜色语义一致（同一会话内红色永远 = 危险/失败）
- [ ] 有标题，且标题是结论句而非主题词（"设备故障导致停机的因果链" ✓；"系统架构图" ✗）
