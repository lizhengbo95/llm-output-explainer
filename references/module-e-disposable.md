# 模块 E：一次性演示工具（Disposable Demo Tools）

**定位**：沟通受阻场景——有距离、有层级、有立场时，**演示优于讲述**（Demo beats description）。
**核心心智**：受众不是被说服的，是被展示的；演示结束后，工具可以死，结论留在受众脑子里。

**定位补充**：本模块与模块 C 级别 4 是同一形态。区别只在用法：C4 是"讲解的交互增强"，E 是"用工具代替讲话"。当 Q4（读完要做什么）的答案是"改变看法/认可结论"且受众有立场阻力时，选 E。

## 铁律：用完即弃（This Will Be Deleted）

Anthropic eval 团队为此专门设了 over-engineering eval：不声明"用完即弃"，agent 必然写出会被误当成正式产品的代码，然后它被合并、被维护、变成债务。

因此生成时必须显式声明：
1. **目录约定**：输出到 `demos/<日期>-<主题>/` 或 `/tmp/`，不进项目主目录
2. **头部声明**：文件首行注释 `// DISPOSABLE PROTOTYPE - built to answer one question, then die.`
3. **禁止事项**：不写测试、不写错误处理、不做抽象层、不优化性能、不写 README（最多 5 行使用说明）
4. **唯一持久产物是结论**：工具回答一个问题（"A/B 哪个好？"该不该换？"），结论是文本交付物，工具本身可删

## 选例（Example Picks）

| 场景 | 一次性工具 | 回答的问题 |
|---|---|---|
| 方案对比 | 双栏参数滑块对比页 | "改这个参数，结果差多少？" |
| 优先级分歧 | 拖拽排序看板（30 张票卡，预排序+复制结论按钮） | "先做哪些？砍哪些？" |
| 进度对齐 | 真实数据仪表盘（读一次 CSV，不做刷新） | "现在到底什么状态？" |
| 技术选型 | 最小对比实验（两个 API 各调 3 次，摆结果） | "哪个在我们的数据上更准？" |
| 预算挑战 | 成本模拟器（输入假设→输出 3 年曲线） | "这笔钱花出去是什么形状？" |

## 生成流程

1. 确认场景属于"演示优于讲述"（有立场阻力/抽象分歧）；否则回矩阵
2. 写清楚一句话："这个工具要回答的问题是 ___"
3. 从模块 C 模板派生，默认级别 3-4，加载真实数据（哪怕是手搓的 10 行 JSON）
4. 内置"导出结论"按钮（Copy as markdown：最终状态 + 一句话理由）
5. 交付：文件路径 + 一句使用说明 + 明确说"这是用完可删的演示件"

## 验收清单

- [ ] 文件首行有 DISPOSABLE 声明，目录在 demos// 或 /tmp/
- [ ] 无测试、无错误处理、无抽象层（发现就是违反）
- [ ] 打开即用，零配置（受众不会给你第二次机会）
- [ ] 有"导出结论"路径——工具死了结论还活着
- [ ] 没有看起来能进生产环境的痕迹（命名、注释、结构都不像正式代码）
